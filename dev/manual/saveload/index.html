Saving and loading

save_system(path, sys) writes a solved System to a JLD2 (HDF5) file, and load_system(path; on=Array) reads it back, ready for energies, port, derivatives and the QuantumToolbox functions. load_metadata, system_nodes and load_node read your notes or one node without loading the rest.

using KronFreeCircuits
spec = load_spec("two_transmons.json")
θ = (E_J1=30.0, E_C1=1.2, n_g1=0.25, E_J2=25.0, E_C2=1.0, n_g2=0.0, g=0.3)
leaf(i) = Node([Symbol("varphi_$i") => ChargeBasis(20)]; keep=lowest(6))
sys = materialize(Node([leaf(1), leaf(2)]; keep=lowest(10)), spec, θ)

path = joinpath(mktempdir(), "two_transmons.jld2")
save_system(path, sys; metadata=(note="g = 0.3",))
sys2 = load_system(path)
energies(sys2) == energies(sys), load_metadata(path)
(true, Dict{String, Any}("note" => "g = 0.3"))

A system solved with a custom solver loads without that solver's code (only a new solve needs it); pass load_system(path; solvers=[MySolver]) to get the solver itself back.

The file

JLD2 files are HDF5, and this one holds only numbers, Bool, strings and arrays of them, so it can be read without KronFreeCircuits (see Reading with h5py). Files are uncompressed.

save_system("kite.jld2", sys; metadata=(note="optimum",))   # retained=false drops the retained eigenvectors
sys2 = load_system("kite.jld2"; on=Array)                   # on picks the device; callbacks come back as nothing
load_metadata("kite.jld2")                                  # Dict("note" => "optimum"), reads no results
system_nodes("kite.jld2")                                   # positions of the solved nodes: [[], [1], [2], ...]
load_node("kite.jld2", [1])                                 # (; energies, kept, vectors, dims, ports, solver, custom, on) of one node

Layout

format                  "KronFreeCircuits.System"
format_version          1
package_version         e.g. "0.1.0"
saved_without_retained  true; present only when saved with retained=false
metadata/<key>          your notes (numbers, Bool, String, or arrays of them)
spec                    the spec as JSON text (spec_json); absent for a system built without a spec
constant, constant_deps the constant term as a coefficient string and its parameter names; present only
                        when terms/from_spec is false
terms/from_spec         true: the terms are rebuilt from `spec`, and `terms/*` holds only the extra terms
terms/coefficients      one coefficient string per stored term
terms/deps/<i>          parameter names of coefficient i
terms/factor_term       one entry per factor: its term index
terms/factors/{modes,kinds,ks}
                        one entry per factor: its mode, port kind and port k
theta/names             parameter names
theta/values/<i>        the parameter point, one tagged value each
root/                   the root node (below)
augmented/count         number of augmented children
augmented/<i>/          node_path (child indices from the root), solved/ (a node group), basis, terms/ (as
                        above), theta/, report/labels, report/taken, report/dropped

A node group (root, <node>/children/<i>, augmented/<i>/solved):

kind                    "node" or "given" (a GivenSystem)
eltype                  "Float64" or "ComplexF64"
dims, energies, vectors, kept, peak_component, peak_amplitudes
ports/count             ports/<i>/{modes,kinds,ks} (one entry each) and ports/<i>/matrix
joint_ports/count       joint_ports/<i>/{modes,kinds,ks} (the factor list) and joint_ports/<i>/matrix
retained/energies, unkept, complete, followed
retained/vectors        absent when nothing was retained, or when saved with retained=false
settings/solver, settings/keep      a struct: `type`, then `fields/<field>`; the solver also has
                                    `custom` (true for a user-defined solver)
settings/solver_used    the solver that ran, when it differs from settings/solver (what `Auto` picked)
settings/{compute,phase,arithmetic,retain}   tagged values
settings/ports/{modes,kinds,ks}     the node's port list
children/count          children/<i> is a node group, or a leaf:
                        kind "leaf", mode, basis (a struct)

A given node has instead settings/mode, settings/given_energies, settings/operator_names and settings/operators/<name>; it has no children.

A struct is <name>/type (a solver, selection rule or basis name such as "Lanczos") and <name>/fields/<field>, one tagged value per field. A tagged value is <name>/kind plus <name>/value, where kind is one of int, float, bool, string, ints, floats, strings, matrix_real, matrix_complex, symbol (stored as a string), nothing (no value), port (value is the port kind, plus k), modeport (mode, port_kind, k), arraytype (the array type's name) or unsaved (a custom solver's setting that is not one of these kinds; value is its type). The saved device is at settings/solver/fields/on/value; callbacks are stored as nothing.

Behaviour

  • Coefficients are stored as strings in the spec grammar, plus Complex(re, im) and Rational(num, den) literals. save_system refuses (with an ArgumentError) a coefficient that would not parse back identically.
  • Spec-built systems store the spec (spec) and only the terms added to it afterwards.
  • retained=false sets /saved_without_retained = true and retained/complete = false on every node whose vectors were dropped. Derivatives of such a system take the slower paths for a node without retained vectors and agree with the original's to solver tolerance, not bit for bit.
  • Callbacks are not saved; a loaded solver's callback is nothing.
  • Device: load_system(path; on=Array) sets on on every solver that has the field. The saved device is only recorded: load_node(path, pos) returns it as on, with the name of the solver that ran as solver (for Auto, the solver it picked, saved at settings/solver_used; the loaded system keeps Auto) and whether it is user-defined as custom. Dense and ShiftInvert run on the CPU and report on = "Array"; any other solver without an on setting reports nothing, as does a given node (a GivenSystem), which has no solver.
  • Custom solvers: a node solved with a user-defined solver is saved with the solver's name and settings, so the file can be shared with someone who does not have the solver's code. load_system(path) then gives that node a SavedSolver holding the name and settings: the saved results, ports and derivatives work, and only a new solve of that node throws. load_system(path; solvers=[MySolver]) rebuilds the real solver from its settings, unless one of them could not be saved (it then warns and keeps the SavedSolver).
  • Versions: /format_version is 1. load_system reads only the versions it knows and otherwise throws an ArgumentError naming the file's version; a future format change bumps the number, and a newer package will keep reading version 1 files.

Reading with h5py

import h5py

h5py.get_config().complex_names = ("re", "im")      # complex arrays are stored as (re, im) compounds
with h5py.File("kite.jld2", "r") as f:
    E = f["root/energies"][()]                       # eigenvalues
    V = f["root/vectors"][()]                        # transposed: Julia is column-major, so V[j] is eigenvector j
    kind = f["root/kind"][()].decode()               # strings come back as bytes
    n_leaves = f["root/children/count"][()]
    # Bool comes back as uint8
    complete = bool(f["root/retained/complete"][()])

Matrices (vectors, ports/<i>/matrix) come out transposed relative to Julia; use V.T for the Julia orientation.
