KronFreeCircuits.Spec — Type
Spec

A circuit Hamiltonian in the canonical form `4 (n-ng)ᵀ EC (n-ng) + ½ φᵀ EL φ + φᵀ flux_linear - Σ energy cos(omegaᵀφ + offset)

  • Σ energy cos(2π kappaᵀ(n-n_g) + offset) + constant`,

with every coefficient a compiled expression of the named parameters. Matrices and vectors are indexed in the order of modes.

KronFreeCircuits.parse_spec — Function
parse_spec(json::AbstractString) -> Spec

Parse and validate a kronfree-spec version 1 JSON document. Keys starting with _ are ignored; any other unknown key is an error. Every expression (E_C, E_L, flux_linear, n_g, cosine and charge-cosine energy and offset, constant) must be real-valued: one that uses im or calls cis or cispi is rejected. E_C and E_L must be symmetric: identical entries [i,j] and [j,i] pass; otherwise the pair is rejected if either entry is not real-analytic (the syntactic gate of classify: abs, sign, or a branch cut), and an analytic pair must agree at three fixed pseudo-random parameter points (to 1e-12 relative). Throws ArgumentError on any invalid content.

KronFreeCircuits.numeric_spec — Function
numeric_spec(; modes, E_C, E_L, flux_linear, n_g, cosines=Tuple[], constant=0.0, symmetry_tol=1e-10,
               zero_rtol=1e-12, zero_atol=0.0) -> Spec

A Spec with no parameters from plain numeric arrays, the same Spec that parse_spec builds from a JSON document of the same numbers. modes is a vector of name => type pairs with type one of :c, :e or :h. E_C and E_L are N×N real matrices, flux_linear and n_g real vectors of length N = length(modes). Each cosine is a tuple (energy, omega, offset) with omega a real vector of length N; an omega entry on a compact mode within 1e-12 of an integer is rounded to it, any other is rejected. parse_spec stores such an entry of a JSON document as written, unrounded, so a compact omega of 1 + 1e-13 is exactly 1.0 here and 1 + 1e-13 there. Every coefficient is a constant (nothing is compiled), and an exact zero is a literal zero, as "0" is in a JSON spec. E_C and E_L are symmetrized at round-off level: with scale the largest magnitude in the matrix, a pair [i,j], [j,i] differing by at most symmetry_tol * scale is replaced by its mean, and a larger asymmetry is rejected. Round-off is then zeroed, as circuit-quantization's to_spec does with the same keywords. In the symmetrized E_C and E_L, every entry (diagonal included) at most max(zero_rtol * scale, zero_atol) in magnitude becomes exactly zero, with scale the largest magnitude in that matrix. In each cosine, an omega entry at most zero_rtol times the largest magnitude in that omega becomes exactly zero, on a compact mode at most zero_rtol times the smaller of that magnitude and 1; zero_atol does not apply to omega. zero_rtol = 0, zero_atol = 0 turns zeroing off, and zero_rtol ≥ 1 zeroes every entry of E_C and E_L, whole matrices. Unlike the exporter, which zeroes only floating-point residue and skips a matrix with a symbolic entry, every entry here is a number, so any entry within the threshold is zeroed. The caller's arrays are not modified. Throws ArgumentError on a negative or non-finite zero_rtol, zero_atol or symmetry_tol (naming it, before any other check), a Bool entry, a wrong shape, an unknown mode type, a repeated or missing mode name, a non-finite number, a larger asymmetry (naming the pair) or a non-integer omega on a compact mode.

KronFreeCircuits.promote_mode — Function
promote_mode(spec::Spec, mode::Symbol; parameter::Symbol=mode) -> PromotedSpec

Fix the coordinate of mode (the slow mode s) at the value of a new parameter parameter, giving a spec over the remaining (fast) modes. Each part of spec carries over exactly: E_C[s,s] and n_g[s] are dropped from the fast spec (an @info says so; they are in the result for the slow stage); E_L[s,s] becomes the constant ½ E_L[s,s] p²; E_L[s,f] adds E_L[s,f] p to flux_linear[f]; flux_linear[s] becomes the constant flux_linear[s] p; a cosine with omega[s] ≠ 0 keeps its other multipliers and its offset gains omega[s] p, or, if it has no other multiplier, becomes the constant -energy cos(omega[s] p + offset). Constants accumulate onto spec.constant, and parameter is appended to the parameters. The offset-charge constant 4 n_gᵀ E_C n_g loses its (s,s) part with E_C[s,s] and n_g[s].

Throws ArgumentError if mode is not a mode, spec has only one mode, E_C[s,f] is not (structurally) zero for some fast mode f, a charge cosine has kappa[s] ≠ 0, or parameter is already a parameter, the name of a fast mode, or a reserved name. The checks look at the coefficient expressions, never at parameter values: remove a coupling that vanishes only at particular values first with substitute.

KronFreeCircuits.circuit_terms — Function
circuit_terms(spec::Spec) -> Vector{Term}

Expand the spec into product terms (the constant is excluded; see constant_term). Terms whose coefficient is identically zero are dropped.

The expansion is the same for every basis: the quadratic form 4 (n - n_g)ᵀ E_C (n - n_g) becomes the diagonal terms 4 E_C[i,i] n_i² (n2port()), the cross terms 4 (E_C[i,j] + E_C[j,i]) n_i n_j (nport() ⊗ nport()), the linear terms -4 Σ_j (E_C[i,j] + E_C[j,i]) n_g,j n_i (nport()) and the constant of constant_term, so the offset charge enters only through the linear and constant pieces. A compact mode on a PeriodicGrid is expanded exactly like one in the charge basis (the periodic gauge, design 2026-10-30); a literal n_g = "0" drops its linear term.

KronFreeCircuits.suggest_bases — Function
suggest_bases(spec, θ = (;); charge_cutoff = 16, max_points = 120, extent_scale = 1.0, order = 8,
              when_capped = :warn) -> Vector{Pair{Symbol,Basis}}

A basis for each mode of spec at θ, as mode => basis pairs in the order of spec.modes. A compact mode gets ChargeBasis(charge_cutoff). Any other mode i gets a symmetric PhaseGrid, sized from the real parts of the coefficients at θ. With E_C = E_C[i,i] and E_L = E_L[i,i], the zero-point width is zpf = (2 E_C / E_L)^(1/4) and the oscillator frequency ω = sqrt(8 E_C E_L). ΣE_J is the sum of |energy| over the cosines whose omega[i] is nonzero, and k_max the largest |omega[i]| among them. The grid spans ±extent with extent = extent_scale * max(6 zpf, sqrt(2 (2 ΣE_J + 12 ω + 4 E_C) / E_L)). Its step is min(zpf / 6, π / (6 k_max)), or zpf / 6 when no cosine touches the mode. It has min(ceil(2 extent / step) + 1, max_points) points and finite differences of the given order.

The cap binds when the formula asks for more than max_points points on a mode. The grid then keeps its extent with fewer points, so its step is larger than the formula's: the mode is under-resolved, the finite-difference kinetic energy is too low, and an energy computed on such a grid (a product energy, a level) is no longer an upper bound of the resolved problem's, and can go below its ground level. when_capped says what a binding cap does: :warn (the default) logs one warning naming every capped mode with the points the formula asks for and the cap, :error throws an ArgumentError with the same content, and :allow caps silently, for a caller that caps on purpose. The bases returned are the same in all three cases. A mode that is not compact and has E_L[i,i] <= 0 or E_C[i,i] <= 0 is an ArgumentError, as are charge_cutoff < 1, max_points < 2, extent_scale <= 0 and a when_capped other than :warn, :error and :allow.

KronFreeCircuits.PeriodicGrid — Type
PeriodicGrid(N; order=8, sectors=1)

Compact-mode phase grid on [-π, π) without the endpoint, φ_i = -π + 2π i/N for i = 0..N-1, spacing Δ = 2π/N, with central finite-difference stencils of the given order (2, 4, 6 or 8) that wrap around the circle (periodic boundary condition, the periodic gauge). The basis carries no offset charge and its operators are parameter-free: the offset charge enters only through the coefficients of the canonical quadratic form 4 (n - n_g)ᵀ E_C (n - n_g) (see circuit_terms), exactly as on every other basis. sectors adds the requirement that N be divisible by it, beyond the harmonics declared on the mode (see check_sectors).

Ports:

portoperator
nport()the cyclic central stencil of -i ∂_φ (imaginary, Hermitian)
n2port()the cyclic central stencil of -∂_φ² (real, symmetric)
expiphi(k), integer kdiagonal e^{ikφ}

Plane waves e^{ikφ} with integer k are exact eigenvectors of both stencils, with symbols σ₁(k) = Σ_j w¹_j sin(jkΔ)/Δ ≈ k and σ₂(k) = -Σ_j w²_j cos(jkΔ)/Δ² ≈ k², so the free rotor's discrete spectrum is 4 E_C (σ₂(k) - 2 n_g σ₁(k) + n_g²); at n_g = ½ the pairs (k, 1 - k) are degenerate only to O(Δ^order). :phi and :phi2 are not served because φ is multivalued on a circle, and :exp2pin is a later item.

KronFreeCircuits.Node — Type
Node(children; solver=Auto(), compute=0, keep=lowest(0), phase, ports=[], arithmetic=:auto, retain=:auto)

A hierarchical unit. Each child is a mode => basis pair, another Node, or a GivenSystem (a pre-diagonalized subsystem); a node's product basis has one axis per child.

  • solver: Auto() (the default), Dense(), Lanczos(), LOBPCG(), ShiftInvert() (a leaf on the CPU) or ChebyshevFilter(). Auto resolves at materialization: Dense() up to 1000 product states (its dense_cutoff); above that, ShiftInvert() at a leaf on Array storage, ChebyshevFilter(on=on) at a leaf on device storage, and LOBPCG(preconditioner=:ritz, seed=:product, on=on) at a branch. An LOBPCG node starts from the previous solution's kept vectors when materialize is given previous (see materialize).
  • compute: how many of the lowest eigenpairs the solver returns; 0 means all (only valid with Dense, or with Auto() on a node that resolves to Dense). Dense builds the full matrix whatever compute is, and uses it only to return the lowest compute pairs.
  • keep: the SelectionRule choosing the kept states among the computed ones.
  • phase: the global-phase convention of the kept eigenvectors, :positive_sector or :follow. :positive_sector makes, at a leaf (all children bases), the largest entry with all coordinates nonnegative real and positive; at a branch, each state's exact full-space amplitude at the joint peak of its dominant product component, computed from the children's stored peak amplitudes, so the children's phase conventions do not leak into it. It defaults to :follow when keep is a follow rule and to :positive_sector otherwise; an explicit phase always wins. :follow needs the previous materialization (previous); at the first point of a sweep, with none, :positive_sector is used.
  • ports: extra (mode, port) operators to form in this node's kept eigenbasis, beyond those its ancestors need (which are inferred).
  • arithmetic: :auto (the default) runs the node in real arithmetic when its structure guarantees a real Hamiltonian at every θ (see the manual's "Real arithmetic" page), else complex. :complex forces complex arithmetic for this node and so for every ancestor. :real asserts the node test: materialize throws an ArgumentError naming the first term whose conjugate image is missing when it fails. arithmetic reports the arithmetic a node was materialized in.
  • retain: whether the node keeps the eigenvectors of the states its solver computed but keep did not select (the retained field of MaterializedNode). :always retains them, :never stores only the computed energies, and :auto (the default) retains them except at a Dense node above 1000 product states. A Dense node that retains computes its full eigendecomposition whatever compute is, and still hands only the lowest compute pairs to keep.
source
KronFreeCircuits.GivenSystem — Type
GivenSystem(mode; energies, operators)

A pre-diagonalized subsystem, a tree child beside Node and mode => basis (a resonator or a qubit from another tool, a subsystem exported from scqubits, a fixed model of a neighbor). energies are its eigenvalues in ascending order; operators maps a port kind (any Symbol) to its k × k matrix in that eigenbasis, k = length(energies).

It materializes to a node with identity eigenvectors and all states kept: its energies are the diagonal term on its parent's axis and its operators are the ports (mode, Port(kind, 0)). Routing never descends into it, so a term whose factors all lie on its mode (a drive or Stark shift) is applied at its parent through these ports. Coupling terms are ordinary Terms naming its mode and a port kind it provides; pass them to the spec-form materialize as extra_terms.

Solvers

KronFreeCircuits.Auto — Type
Auto(; dense_cutoff=1000, on=Array)

The default solver of every Node: it picks a solver for the node at materialization, from the node's kind, product dimension and storage.

  • Dense() when the product dimension N is at most dense_cutoff, or when 0 < compute and N < 3 compute + 5, where the block solvers are unreliable (a node whose children kept their states by an energy window can be small without notice);
  • otherwise, at a leaf (all children bases), ShiftInvert() when on === Array and ChebyshevFilter(on=on) on any other storage;
  • otherwise, at a branch, LOBPCG(preconditioner=:ritz, seed=:product, on=on).

The resolved solvers take their default settings; for other settings, pass the solver explicitly (an explicit solver always wins). compute == 0 (all eigenpairs) is valid only for a node that resolves to Dense; otherwise materialize raises an ArgumentError naming the resolved solver. dense_cutoff = 1000 is the most conservative crossover measured on the benchmark machine: the iterative solvers win from about 700 to 1000 states on a transmon leaf and from 100 to 350 on the other shapes (bench_archive/dense_cutoff/results.md). The warning for a large Dense node (above 10 000 states) applies to any Dense that runs, explicit or resolved (e.g. Auto(dense_cutoff=20000) on a 15 000-state node).

KronFreeCircuits.LOBPCG — Type
LOBPCG(; tol=1e-8, maxiter=1000, preconditioner=:ritz, eta=0.01, guard=4, seed=:product, on=Array, callback=nothing)

Block iterative solver: the JuliaMolSim LOBPCG eigensolver (LOBPCGEigensolver.jl), used through its public interface only.

  • tol: convergence threshold on each residual norm ‖H v − λ v‖ of a unit vector, in the Hamiltonian's energy units; maxiter bounds the iterations. Pairs that have not converged within maxiter raise an error naming the unconverged count and the largest residual; they are never returned silently and never retried.
  • preconditioner: :ritz (adaptive per-Ritz Jacobi: column j of the residual is divided by hypot(D − θ_j, eta), with D the diagonal of H and θ_j the column's latest Ritz value), :jacobi (fixed shifted Jacobi, 1 / (D − σ) with σ = minimum(D) − 1) or :none.
  • eta: the regularization of :ritz, in the Hamiltonian's energy units. The default is taken from the audit fixture (GHz) and must be set for other energy scales.
  • guard: extra columns appended to every block (cold or warm start; random with seed=:random, product states with :product). They are extra states: converged with the rest of the block (a guard still unconverged when maxiter runs out gives a warning), then discarded, and the lowest m pairs of the sorted block are returned. Guards make exact excited-state seeds and sector-confined seeds recoverable in practice; they are not a completeness guarantee. The guard shrinks so that the block fits N ≥ 3(m + guard) + 5. On a stiff grid leaf the guard columns can set the iteration count and emit the guard warning even on a warm start; guard=0 avoids this for warm leaf sweeps at the documented completeness cost. A guard stopping rule is an open item.
  • seed: :product starts the whole block of m + guard columns from product_seed (the lowest product states of the separable part, no random columns), :random from a random block. The product seed is perturbed like X0 (below). A previous solution's vectors (X0) win over either for the first m columns; with :product a warm start's guard columns are the next guard product states by energy (random with :random). The cold retry after a failed warm start is always random.
  • on: the array storage the block lives on (Array, or a device array type).
  • callback: nothing or a function called with the solver's per-iteration info named tuple; its return value is ignored, and an exception it throws propagates unchanged.

The operator dimension must satisfy N ≥ 3m + 5; smaller problems call for Dense(). With guards, a warm start reduces the work in H columns (n_matvec) rather than necessarily the iteration count: the guard columns converge alongside the seeded columns, but once the seeded columns lock, each remaining iteration applies H to only a few active columns. Warm-start columns are perturbed by a vector of norm sqrt(eps) times the column's norm (a fixed pseudo-random direction) so exact eigenvector seeds do not present an exactly zero residual; a warm-start block on which the eigensolver still fails is replaced once by a random block, with a warning. A failure on the (perturbed) product-state seed is retried the same way, logged at debug level only.

KronFreeCircuits.ShiftInvert — Type
ShiftInvert(; tol=1e-8, shift=:auto, shift_margin=5.0, inner_tol=1e-13, krylovdim=0, maxiter=100,
            block=1, slices=1, certify=:auto, maxnnz=10^8)

Leaf solver on the CPU: Lanczos on (H − σI)⁻¹, with H − σI factored directly from the assembled sparse matrix sparse(H; maxnnz). Arithmetic follows the operator's element type: real when eltype(H) <: Real, complex otherwise.

  • tol: the acceptance threshold on each true residual norm ‖H v − E v‖ of a unit vector, in the Hamiltonian's energy units, computed with the package operator. A pair above it raises an error naming the worst residual; pairs are never returned unvalidated. When tol lies below what double precision can deliver, the threshold is the roundoff floor 10 eps·‖H‖ instead (‖H‖ taken as the larger of gershgorin_bound(H) and the lowest energy's magnitude; a debug message reports a pair accepted there), the rule ChebyshevFilter shares. A backward-stable solve, Dense included, leaves residuals of a few eps·‖H‖, and ‖H‖ grows like 1/h² on a phase grid and like ncut² in a charge basis (7e5 on a 4000-point fluxonium grid, 1.6e7 at ChargeBasis(2000) with E_C = 1).
  • shift: :auto puts σ = E_min − shift_margin below a short Lanczos estimate E_min of the lowest eigenvalue, so H − σI is positive definite and is factored by sparse Cholesky. If the estimate overshoots by more than shift_margin and the Cholesky fails, it is retried at E_min − shift_margin·4^r for r = 1, 2, 3, then at the Gershgorin lower bound of H minus shift_margin (a debug message names the shift that worked); only if every retry fails does the solve fall back to LU, with a warning. Slicing (slices > 1) does not retry. A number is used as σ itself; a shift at or above the estimate is interior, H − σI is factored by LU, and the m eigenvalues nearest σ are returned.
  • shift_margin: the distance of the automatic shift below the estimate, in the Hamiltonian's energy units, and the base of the retry shifts above. The default is taken from the zero-pi fixtures (GHz) and must be set for other energy scales.
  • inner_tol, krylovdim, maxiter: KrylovKit's tolerance on the inverted operator (not the acceptance criterion), Krylov dimension (0 lets the solver choose 2m + 10) and restart bound. The converged pairs are then polished: one step of block inverse iteration with the same factorization, and Rayleigh–Ritz with H. A Lanczos pair stops with Krylov residual r just under inner_tol, and H v − E v = −(E − σ)(H − σ) r, so components of r on high-lying states reach the true residual magnified by up to |E − σ|·‖H‖ (up to 1e-5 on 8000-state leaves, with the vectors accurate to 1e-11); the step damps them to the roundoff floor, at about 3 % of the solve time.
  • block: 1 (Lanczos) or 2 (block Lanczos, degeneracy insurance for exactly repeated eigenvalues). Block size 4 reported false convergence in KrylovKit 0.10.4 and is not offered. A block run that KrylovKit breaks off (the square root of a negative residual norm, on a nearly rank-deficient residual block) repeats as single-vector Lanczos.
  • slices: spectrum slicing across threads. 1 is the single-shift solve above. An integer k > 1 locates the range [E_min, E_m] by inertia counts (bisection on the negative pivots of LDLᵀ(H − τI)), cuts it into k contiguous intervals holding about m / k eigenvalues each, and solves each by Lanczos on (H − σ_k I)⁻¹ with σ_k at its center (an LU factorization each), in parallel over Threads.@threads (serially on one thread). The inertia counts certify every interval: one returning a different number of states than its count raises naming it. :auto means Threads.nthreads() slices when there is more than one thread, and 1 otherwise. Slicing finds the lowest m, so k > 1 requires shift = :auto (:auto with an explicit shift is one slice). BLAS and UMFPACK threads are not pinned inside the threaded loop, so many slices on a many-thread machine can oversubscribe the cores. Each inertia count at a cut costs two LDLᵀ factorizations (at τ ± 10·tol, to keep every cut clear of an eigenvalue).
  • certify: count the eigenvalues below a cut τ in the first gap above the m-th computed energy (wider than 2·tol, so a degenerate level is never cut) by the inertia of an LDLᵀ factorization of H − τI, and require it to equal the number of computed energies below τ (a completeness certificate). :auto (the default) certifies whenever the lowest m are sought: when σ lies below the spectrum (Cholesky), automatic or explicit, and with the automatic shift (the path Auto() takes) also on its LU fallback; an explicit interior shift returns the states nearest σ and is not certified. true certifies always (an interior shift then raises unless the states nearest σ are the lowest). Single-vector Lanczos resolves one copy of an exactly degenerate level per Krylov space, so it can return a 4-fold ground level as two copies, with passing residuals; the certificate detects the shortfall. With σ below the spectrum (Cholesky), the missing states (plus one) are then found by Lanczos on the inverse deflated against every computed vector, x ↦ P (H − σI)⁻¹ P x with P = I − V V', merged with the computed ones by Rayleigh–Ritz, and the count repeats while each round recovers a state (a level with c copies takes about c / block rounds; a round that converges none raises); with σ not below the spectrum (LU) a short count raises at once. A certified solve also starts from fewer than m + 1 converged pairs, when a few distinct levels exhaust the Krylov space, and recovers the rest the same way. The certificate costs one LDLᵀ factorization and one more Lanczos pair when it passes (two factorizations if the first breaks down; about +5 % on the 9331-state zero-pi leaf at m = 300), and one more Lanczos run and one or two factorizations per recovery round. certify=false runs no completeness check: a degenerate level may be undercounted, silently. A sliced solve is always certified (its count mismatch raises; it does not deflate).
  • maxnnz: the nonzero cap of sparse(H); a larger operator is refused before assembly.

KronFreeCircuits.ChebyshevFilter — Type
ChebyshevFilter(; tol=1e-8, degree=100, extra=40, maxiter=50, rescale_every=20, ortho=:svqb,
                bound=:gershgorin, seed=:product, on=Array, callback=nothing)

Block leaf solver: Chebyshev-filtered subspace iteration (Zhou–Saad ChFSI) on the package operator, on the host or a device. Each iteration applies to the unlocked columns of a block of nb = m + extra columns (capped at the dimension) the degree-degree Chebyshev polynomial of the first kind on the unwanted interval [λ_cut, λ_max] mapped to [−1, 1], which damps that interval and amplifies everything below it, then orthonormalizes and performs Rayleigh–Ritz.

  • tol: the acceptance threshold on each true residual norm ‖H v − E v‖ of a unit vector, in the Hamiltonian's energy units, computed with the package operator. Columns lock (stop being filtered) in order from the bottom of the block once their Rayleigh–Ritz residual is below tol / 2; the iteration stops when the lowest m + g are locked (g ≤ min(extra − 1, 4) counted guard columns) and no unlocked Ritz value lies below the m-th locked energy. The returned pairs are the lowest m of all locked columns, accepted at tol with a fresh residual from a new application of the operator. Acceptance follows ShiftInvert's rule, the alternative for the same node: when tol lies below the roundoff floor 10 eps·‖H‖, the floor is the threshold instead and columns lock below half of it. Chebyshev's residuals stall higher than ShiftInvert's polished ones on a fine phase grid (about 2.6, 10 and 25 eps·‖H‖ at 1000, 4000 and 8000 points of the fluxonium grid, against 1 to 3), so at 8000 points and tol = 1e-8 it raises at maxiter where ShiftInvert succeeds (4000 points pass); use ShiftInvert on the CPU there, or loosen tol. No column locks, and the iteration does not stop, before the first filter application (unless the block spans the whole space, nb = N): the seed's own Rayleigh–Ritz is never accepted, since a seed spanning an invariant subspace has zero residuals there however far it lies from the lowest states.
  • degree ∈ 1:200: the polynomial degree, i.e. block applies per iteration. An iteration lowers it so that the filter amplifies the lowest Ritz value of the block at most 1/√eps over λ_cut (beyond that the upper columns of the block fall below the resolution of the Gram-based orthogonalization). On a narrow spectrum the cap binds hard (the three-oscillator test runs at degree 14 of 100); on a grid leaf with a large bound it binds moderately (the small zero-pi leaf runs at degree 65–81 of 100). The applied degree is reported to callback and in the maxiter error. It is never raised, so a weak filter (λ_max far above λ_cut) converges slowly but steadily: the residuals fall by about cosh(degree · acosh|x|) per iteration, x the image of the m-th lowest Ritz value on the filter interval mapped to [−1, 1], about cosh(degree · nb / ncut) in a charge basis of 2 ncut + 1 states. On the 7999-state transmon leaf at m = 6 (λ_cut ≈ 2080, λ_max ≈ 6.4e7) that is 1.7 per iteration and the defaults need 52 iterations, so maxiter = 50 raises; degree = 200 converges in 18 and m = 20 (nb = 60, 2.2 per iteration) in 37. The maxiter error says so when the last filter's degree · acosh|x| was below 2 (under about 3.8 per iteration).
  • extra ≥ 2: columns beyond m (they set the convergence rate and absorb near-degenerate states); at least two so at least one column serves as a convergence guard, since the top column sets the filter cut. Up to four of them double as guards that must converge before the iteration stops, as LOBPCG's: g = min(extra − 1, 4), one fewer than extra because the top column sets λ_cut and sits at the cut, where the filter does not converge it (hence extra ≥ 2: with extra = 1 there is no guard, and a lower state outside the seed span can be missed with passing residuals). A guard is waived only while the last filter's log-gain at its Ritz value (degree · acosh|x|, x its image on the filter interval mapped to [−1, 1]) is below 0.1 times the log-gain at the m-th lowest Ritz value, the highest wanted state (so a deep ground state cannot waive the guards protecting the states above it): one (near-)degenerate with the top column gains about nothing and would never lock, while under a filter that is weak everywhere (a spectral bound far above the block) every guard keeps a ratio near 1 and is waited for. Guards near the cut converge slowly, so a small extra can take many more iterations; when guards are what remains unconverged at maxiter, the error advises raising extra or maxiter.
  • maxiter: the bound on filter iterations; running out raises an error naming the converged count.
  • rescale_every: every this many recurrence steps the pair (T_{k−1}, T_k) is divided column-wise by the norm of T_k (the recurrence is linear, so only column scales change), preventing overflow.
  • ortho: :svqb (eigendecomposition of the unit-diagonal Gram matrix, two passes; directions with eigenvalue below 1e-12 times the largest are dropped and refilled with random vectors) or :cholqr (Cholesky-QR, two passes; a numerically rank-deficient block raises, advising :svqb).
  • bound: the upper end λ_max of the filtered interval: :gershgorin uses gershgorin_bound, a rigorous bound; a finite number is used as given. A number below the true largest eigenvalue amplifies the top of the spectrum; it is detected (a Ritz value above the bound, or a non-finite block) and raises an error naming the bound.
  • seed: :product starts from product_seed (the lowest product states of the separable part) plus a fixed random admixture of relative size 1e-2 per column; :random from a random block. The admixture matters when the product states span an exactly invariant subspace that misses a lower state (a coupling acting only among higher product states): the filter's gain per iteration is capped near 1/√eps, so a component of size 1e-2 along that state dominates a column within the first iteration or two, where a √eps one (LOBPCG's perturbation) would not.
  • on: the array storage the block lives on (Array, or a device array type).
  • callback: nothing or a function called once per iteration, after locking, with the named tuple (; iteration, λ, residuals, n_locked, λ_cut, λ_max, degree) (host copies; λ_cut and degree are those of the last filter, NaN and 0 before the first); its return value is ignored.

λ_cut is the largest Ritz value θ_nb of the current block (initially of the seed's Rayleigh–Ritz): every block direction is amplified, the lowest m the most, so the extra columns set the rate. Results are host arrays.

There is no completeness certificate. A lower state outside the seed's span is found only through the random admixture (or the random seed) and the guard columns: it is missed when its overlap with the initial block is so small (below about 1e-2 · G^(−k), with G ≈ 1/√eps the capped gain per iteration and k the iterations the lowest m + g columns take to lock) that it has not surfaced in a column by then, and the stop rule then accepts the lowest states found. ShiftInvert() (inertia certificate, on by default with the automatic shift) is the certified path.

The defaults (seed=:product, extra=40, degree=100, tol=1e-8) were tested against invariant-seed traps, weak filters, crossing sweeps, degenerate blocks and deep references without a wrong result, but this is tested, not proven. The stop is residual-based, so a state outside the product-seed span is found only if the filter lifts its admixture of about 1e-2/√N to O(1) before the m wanted and up to 4 guard columns lock. This can fail silently with a weak filter (a low degree, or a spectral bound far above the block) combined with a loose tol, or at a small extra. Use tol ≤ 1e-6 and the default or a larger extra, and ShiftInvert() (certified) or Dense() when completeness matters.

Solving and reading results

KronFreeCircuits.materialize — Function
materialize(root, spec, θ; previous=nothing, extra_terms=Term[], augmented=AugmentedChild[]) -> System
materialize(root, terms, θ; constant=Coefficient(0), previous=nothing, modetypes=Dict(), augmented=AugmentedChild[]) -> System

Diagonalize every node of the tree under root at parameters θ, children first. The first form expands spec with circuit_terms and constant_term, appends extra_terms (terms not in the circuit spec, such as couplings to a GivenSystem), and delegates to the second, which takes a user-built (filtered, transformed) term list and a scalar constant. The second checks every PeriodicGrid against the harmonics k of every expiphi(k) factor on its mode in the term list (the spec's cosines and extra_terms alike): k must be an integer and divide the grid size (check_sectors).

The constant is added at the root only: the energies of every child node exclude it. previous, a System of the same tree, supplies each node's previous solution (same tree position) to the :follow phase convention, to selection rules, and to LOBPCG nodes as their initial block. That block is the previous kept vectors (their raw coefficients in the node's product basis), padded on the right with random columns to compute or truncated to it; a node whose dims changed starts cold. Only the kept vectors seed it, so when compute > keep the remaining columns start random and the block is only partially warm. A node that retains (its retain option, see Node) also stores the vectors its solver computed but did not keep, and every node stores all its computed energies (the retained field of MaterializedNode); a retaining Dense node computes its full decomposition and stores the whole spectrum. The follow rule and the :follow phase compare physical overlaps: the previous kept vectors are first transported into the current product basis through the overlaps of the previous and current child kept states, computed recursively (the identity on basis axes). This needs, at every such node and below it, the same product dims and equal bases on basis axes; otherwise an ArgumentError is thrown (overlaps across different primitive bases are not implemented, and equal dimensions alone do not establish the same basis). A parameter missing from θ, or one whose value is not of a Real type (all system parameters are real; pass a complex amplitude as two real parameters), raises an ArgumentError naming it.

Each mode => basis leaf child is checked against the mode's type: a compact mode (:c) needs a ChargeBasis or PeriodicGrid, an extended (:e) or harmonic (:h) mode a PhaseGrid or FockBasis. The spec form takes the types from the spec; the term-list form from modetypes (mode => type), skipping modes absent from it (an empty dictionary skips the check).

Every node is classified once, from the term list and the tree, as real or complex arithmetic (its arithmetic option; see Node); a node with arithmetic = :real whose structure does not guarantee a real Hamiltonian throws an ArgumentError.

A term routed to a branch node with two or more factors inside the same child is applied through that child's joint port (joint_ports of MaterializedNode): the operator V† (⊗ₐ Oₐ) V of those factors, formed in the child's product basis before its projection onto the kept states, never a product of separately projected single ports. A term with two or more factors on one mode throws an ArgumentError.

augmented, a vector of AugmentedChild (from augment), presents some nodes of the tree through a basis of their own: such a node is not solved, and its solved is used as that child, with any port or joint port the tree needs that it lacks formed from its kept vectors. The terms are routed as usual, so the terms inside an augmented node are not used, and its ancestors' operators are built exactly as on a solved child. An augmented child is used as built, at the terms and θ that augment was given; it is the caller's job to rebuild it when they change. A θ that differs from the augmented child's in a parameter its stored (bare) terms depend on is an ArgumentError; the terms themselves are not checked, nor the parameters of the terms inside a branch child. An augmented node, and every ancestor of it, runs in complex arithmetic. The System records the augmented children, which augmented returns. An augmented node that is not in the tree or is its root, a node given twice, an augmented node inside another one, augmented together with previous, and an augmented node or an ancestor of one with arithmetic = :real each throw an ArgumentError.

Derivatives

KronFreeCircuits.derivatives — Function
derivatives(sys::System; wrt, order=1, mixed=(), scale=(;), r=0.1, degenerate_tol=1e-9, lintol=1e-10,
            linmaxiter=5000, given_independent=false) -> Derivatives

The first derivatives, along each parameter of wrt, of every kept energy, kept vector, port and joint port of every node of the materialized tree sys, by perturbation theory carried upward through the tree; with order = 2 also the second derivatives along each parameter of wrt alone and along each pair of mixed. They are the derivatives of the calculation as performed: the selection of kept states, the bases, the solvers, the real or complex arithmetic of every node and its discrete phase choice (its peak indices, peak_component) are held fixed, and nothing is re-solved. Each node's ∂H/∂x has three contributions: the derivatives of the coefficients of the terms routed to it (and, at the root, of the constant), its children's port and joint-port derivatives, and its children's energy derivatives. The element types are those of the stored quantities: Float64 energies, and vectors and ports of the types materialized stores them in. A node whose subtree (and, at the root, the constant) does not depend on a parameter is not visited and reads as zeros. At second order a node's ∂²H/∂x∂λ has the same three contributions by the product rule, and a node whose subtree does not depend on both parameters reads as zeros.

Cost: one first-order pass per parameter and, with order = 2, one second-order pass per parameter and per mixed pair, each about one resolvent application (a linear solve at an iterative node) per kept state per node it visits. A second-order pass rebuilds the operators ∂H/∂x, ∂H/∂λ and ∂²H/∂x∂λ at each node; only the first-order data and each node's resolvent are kept between passes. Every parameter's first-order data for the whole tree is kept in the returned object, so its memory grows with the number of parameters; order = 2 runs the single-parameter second-order pass for every parameter of wrt. The pass reads node.solver and node.compute from the tree, so the tree must not be modified between materialize and derivatives.

Keywords:

  • wrt: a parameter name or a collection of names, each a key of sys.θ; duplicates are removed. A name that nothing in the system depends on (no term, no augmented child's bare term, not the constant) is an ArgumentError when the system's spec does not declare it, and otherwise gives zeros with one warning ("nothing in this system depends on :x; its derivatives are zero").
  • order: 1 (first derivatives) or 2 (also the second derivative along each parameter of wrt alone).
  • mixed: the pairs of parameters whose mixed second derivatives are wanted, a collection of pairs such as ((:E_J, :varphi_ext),), each of two different parameters of wrt; a pair given in either order is the same pair. mixed = :all asks for every pair of wrt (the full Hessian with order = 2; n(n − 1)/2 second-order passes for n parameters). A nonempty mixed needs order = 2.
  • scale: a NamedTuple of typical displacements δx of parameters in wrt, positive and finite, for the near-degeneracy test |⟨ψ_l|∂H/∂x|ψ_i⟩| δx > r |E_i − E_l|.
  • r: the ratio of that test, positive. At every visited node, the pairs of kept states it flags along a parameter, and the pairs exactly degenerate (within degenerate_tol) with a nonzero coupling, at first order or at second order through other states, are grouped into blocks, read through blocks; each carries the effective Hamiltonian that block_levels diagonalizes at a finite displacement (see NearDegenerateBlock). The point derivatives are not changed by the blocks. Forming a block's second-order pieces costs two resolvent applications (linear solves at an iterative node) per pass, on as many columns as the block has states. The pass also runs the selection-boundary test at every visited node: a kept state close to an unkept computed state (by the test above when scale has an entry for the parameter, else when their detuning is at most 1e-6 times their distance from the node's lowest computed energy), or degenerate with one it couples to, is recorded in boundary with one warning per node and parameter, since the derivative at a fixed selection is fragile there. States beyond a node's compute were never computed and cannot be tested. A kept state that clashes (is degenerate with a state its right-hand side couples to) only at second order has NaN second derivatives with a warning; a clash with an unkept computed state is also recorded in boundary, with the pair _pairkey(x, λ) of the pass as its parameter.
  • degenerate_tol: the detuning (GHz) at or below which two states are exactly degenerate, nonnegative; a kept state degenerate with a state it couples to has NaN derivatives. A child whose derivative is NaN makes the derivatives of its ancestors' states that involve it NaN (design P5), with one warning per node and pass naming the child, and no error, degeneracy warning or block at the ancestors on that account; the child's own block stays available.
  • lintol, linmaxiter: the relative tolerance (positive) and iteration limit (positive) of the linear solve at a node without its complete spectrum (an iterative node): the part of each state derivative orthogonal to the node's computed states solves (E_j − H) w_j = (∂H/∂x) ψ_j on their orthogonal complement by a Jacobi-preconditioned conjugate gradient. Its right-hand side is (∂H/∂x) ψ_j with its components on the computed states subtracted, and each column's residual must reach lintol times that complement part's own norm ‖Q (∂H/∂x) ψ_j‖. For a parameter internal to a weakly coupled child that right-hand side lies almost inside the computed states, and its complement part can be so small that this target is below round-off (about eps ‖(∂H/∂x) ψ_j‖): such a column stops at the round-off floor, when its true residual has stopped decreasing and is at most 1000 eps times the whole right-hand side, and is recorded as such; a column whose complement part is already below that cap is converged from the start (no solve). Each solve's true residual is checked and recorded in linear_solves (residual, from_start, at_floor, floor_residual); a column that misses both its target and the round-off cap is an error. A column at the floor or converged from the start is accurate to about 1000 eps ‖(∂H/∂x) ψ_j‖ / gap in absolute terms, gap the distance from E_j to the lowest state outside the computed ones; this exceeds 1e-6 of ‖∂ψ_j‖ when ‖∂ψ_j‖ gap / ‖(∂H/∂x) ψ_j‖ < 2.2e-7 (on the two-transmon test tree, a parameter internal to one transmon at couplings below about 3e-5). The iteration count grows roughly linearly with a grid leaf's point count (measured: 744, 1505 and 3055 iterations at 3001, 6001 and 12001 points at the default settings), so linmaxiter may need raising for very fine grids. A node with retain = :never projects out its kept states alone, which must then be its lowest computed ones, and records no selection-boundary pairs (its unkept computed states are not known).
  • given_independent: declares the GivenSystem children independent of every parameter. Their energies and operators are numbers whose dependence on the parameters is unknown, so without it a tree with a GivenSystem child is an ArgumentError; with it they have no derivative data, like a basis, and read as zeros.

An augmented child (see augment) is differentiated as its bare operator projected on its fixed stored basis. Its stored states are the whole spectrum of that projected problem, so its resolvent is the sum over them, with no linear solve, no re-diagonalization and no selection boundary. Its ∂H/∂x is the derivative of its bare operator: of the coefficients of its stored bare terms (not of the terms the tree routes to it) and, when its children are nodes, their port and energy derivatives, computed by the ordinary pass on the terms the tree routes to them; its gauge is its own phase rule, and the basis coefficients do not move. This is the derivative of the calculation with the basis held fixed, not of a re-run of the mean-field loop that chose it. An augmented child built at a θ that differs from sys.θ in a parameter that a term inside it depends on (its bare terms or the terms of any node below it) is an ArgumentError.

A Born–Oppenheimer reduced spec is an ordinary spec: a slow_spec carries no dependence on the fast parameters, and a fit_surfaces spec carries the fitted-over parameters through its fit model, so derivatives with respect to them are derivatives of the fit.

A node whose phases followed a previous solution (phase = :follow with previous) is an ArgumentError.

Solved nodes

On a node of a solved system (the root by default) the states are the node's kept states, states selects some of them (an index, a range or a vector; the state axis is kept), and the node must be a leaf: every child a basis. A branch node throws.

On a leaf with several modes the result is (axes, ψ): axes is a NamedTuple of the modes' grids keyed by mode name, in the node's mode order, and ψ[i₁, …, i_N, s] is state s at the grid points, each mode transformed by its rule above (the modes in charge, a mode name or a collection of them, to charge; the others to phase). A FockBasis mode takes its points per mode, points = (phi = φs,). The result is real when every transform keeps the state real, ComplexF64 otherwise. A leaf with one mode keeps the one-mode form (φ, ψ), and its points may also be passed positionally.

Limits:

  • The charge resolution of a PhaseGrid is fixed by its window: Δn = 2π/(NΔ) over |n| ≤ π/Δ (Δn ≈ 0.1 for PhaseGrid(-10π, 10π, 601)). A finer charge grid needs a wider phase window.
  • A PhaseGrid holds both endpoints, so the transform's period is NΔ, one step more than b - a; this is harmless for a state that vanishes at the edges of the grid, and wraps the state around otherwise.
  • The charges of an even-N PeriodicGrid are not those of a ChargeBasis, which always has an odd dimension.
  • A grid basis discretizes n by finite differences, so the result is the state's representation in charge, not an eigenvector of the Hamiltonian written in a charge basis.

Write the solved sys to the JLD2 file path (format version 1: plain arrays, numbers and strings, one group per tree node), to be read back by load_system. Solver callbacks are not saved.
